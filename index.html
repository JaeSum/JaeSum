Bella: AI customer support pipeline

Grew it from a hackathon prototype into a production system handling support tickets across 3 markets.

n8nZendesk APILLMsRAGBigQueryJavaScript
Zendesk ticket→ Clean & de-spam→ Live customer lookup (MY/ID/PH)→ LLM intent→ Reply in EN / MS / IDor RAG agent drafts note for an agent

Problem

Support agents spent hours answering the same questions about credits, transactions and accounts, in three languages, while having to look up each customer by hand.

What I built

A pipeline that reads each ticket's intent, pulls the customer's live account data and sends a personalised reply in English, Malay or Indonesian. Reply rules can be changed without code.

Key decisions

  • The AI agent only drafts internal notes and never replies to customers on its own, which keeps people in control.
  • Repeat tickets get a clearer re-explanation instead of the same reply twice.
  • Tickets with more than one problem get a separate run for each issue.

Also handles

  • Merging duplicate tickets automatically
  • Following up on pending transactions and missing credits on a schedule

Company-wide transaction reconciliation system

The system the whole business uses to reconcile its payouts every day.

Power Query (M)ExcelData modellingn8n
13 provider statements→ Parser for each provider→ Normalised ledger→ Cutoff-aware status matching→ Exceptions to review

Problem

Payouts go through 13 banks and payment providers in 3 countries, and every provider exports in a different and often messy format. Matching 300K+ transactions a month by hand was slow and easy to get wrong.

What I built

A reconciliation model with a parser for each provider and shared filtering logic, which matches every payout against bank records and flags only the exceptions.

Key decisions

  • Matching follows each bank's own cutoff time, so late-evening transactions land on the right day.
  • Detects and handles one provider's two different export formats automatically.
  • Custom parsing for files that break standard CSV rules.

Scale

  • 300K+ transactions a month
  • 13 providers across MY, ID and PH

Wage-credit data pipelines & ops MCP server

Reliable pipelines that turn client attendance and HR files into wage credits, plus a safe way for AI assistants to investigate and fix data.

n8nSFTPAzure Cosmos DBAzure Blob StorageMCPREST APIs
Client SFTP files→ Parse & dedupe→ Dry run / review→ Credit to employees→ Rollback if needed

Problem

Employees' earned-wage credits depend on attendance and HR movement files from enterprise clients, each with its own format and its own quirks. A single mistake affects real people's pay.

What I built

Scheduled pipelines that collect client files, dedupe them against what's already been credited and apply onboarding, resignation and suspension changes, with dry runs and rollback.

Engineering choices

  • Idempotent processing: deduplication and watermarks, so nothing is credited twice.
  • Dry-run mode and a rollback workflow for every risky change.
  • Login-protected review queue for records that need a person to check them.

MCP server

  • 6 tools that let AI assistants look up transactions across markets and check wallet balances.
  • Data fixes run in two steps, prepare then execute, with optimistic concurrency so nothing is overwritten.
Impact: [X employees credited daily] across [X] enterprise clients; [manual uploads removed].
